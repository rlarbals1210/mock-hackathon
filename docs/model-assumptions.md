# 매칭 엔진 계산 근거와 MVP 가정

이 문서는 심사·시연 시 학습 모델 결과와 시뮬레이션 가정을 구분하기 위한 기준이다.

## 배차시간 공식

```text
예상 배차시간(분) = 266 / max(후보 수, 1)^0.354
```

`266`과 `0.354`는 실제 배차 이력에 회귀해 구한 계수가 아니다. `ai/generate_data.py`의 `tdisp()`에 정의된 **v13 경매 시뮬레이션 설계 상수**이며, 생성 데이터의 `배차소요_분`도 이 식으로 만들어졌다. 따라서 별도의 R²나 회귀 적합도는 없다. 온라인 엔진은 생성 데이터와 같은 세계관을 재현하기 위해 동일한 식을 사용한다.

실제 서비스로 전환할 때는 실제 `후보 수 → 배차 완료시간` 관측값으로 생존분석 또는 회귀 모델을 다시 적합하고, 검증기간·오차지표와 함께 버전화해야 한다.

## 운행비용 공식

```text
유류비 = 적재 주행거리 / 톤급별 연비 × 경유 가격 + 톨비
공차비 = 공차거리 × 톤급별 km 비용
예상 실수령 = max(0, 운임 - 유류비 - 공차비)
```

| 톤급 | 연비 가정(km/L) | 공차비 가정(원/km) |
|---:|---:|---:|
| 5톤 | 4.3 | 850 |
| 11톤 | 3.2 | 1,050 |
| 25톤 | 2.4 | 1,350 |

경유 가격은 `1,650원/L`로 둔다. 이 연비·유가·공차비는 현재 저장소의 실측 학습값이나 공식 고시값이 아니라 **MVP 비용 비교용 시나리오 가정**이다. 제품 화면에서는 “예상 비용”으로만 표시하며 실제 정산액으로 표현하지 않는다. 운영 전에는 날짜가 있는 유가 데이터와 차량별 실연비·운영비 설정으로 교체해야 한다.

코드의 단일 기준은 `backend/app/services/assumptions.py`다.

## 운송인 추천점수

선호 쿼리가 없을 때 기존 점수는 다음 요소를 합산해 0~100으로 제한한다.

- 이행률 25점
- 과거 수락률 15점
- 운송인 마스터의 선호 도착권역 20점 또는 8점
- 공차거리 최대 25점
- 운임 대비 예상 실수령 비율 최대 15점

선호 쿼리가 있으면 권역·공차 한도·운행시간 한도·상차 시간대·수익률의 적합도를 0~100으로 계산하고, `기존 점수 75% + 사용자 선호 적합도 25%`로 최종 점수를 만든다. 선호는 필수조건 필터가 아니므로 조건 밖의 콜을 숨기지는 않는다.

세부 지역은 v13 엑셀에 별도 시·도 컬럼이 없어 출발지명의 지명 토큰으로 판정한다. `복화 가능성`은 현재 콜의 도착 권역에서 운송인의 차고지 또는 기존 선호 권역으로 향하는 참조 노선이 존재하는지를 보는 MVP 지표다. 실제 날짜·차량 점유·두 번째 콜 확정까지 최적화한 복화 모델은 아니므로 화면에서도 “복화 후보 노선 있음”으로만 표현한다.

추천 목록은 최종 점수순으로 정렬한 뒤 동일 노선을 제거한다. 요청한 개수보다 실제 적합 노선이 적으면 중복 콜로 채우지 않고 더 적은 개수를 반환한다.
